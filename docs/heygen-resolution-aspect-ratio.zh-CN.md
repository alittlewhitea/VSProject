# HeyGen 高分辨率与比例联动

2026-11-12。针对文生视频报错 `1080p and 2K resolution only support '16:9' and '9:16' aspect ratios`。应用侧修改及本地验证完成，提交状态以 Git 记录为准，生产发布仍需部署。

## 原因

旧模型配置独立列出全部分辨率和全部比例，没有描述它们的组合限制。界面允许提交 1080p/2K + 1:1、4:3 等组合，服务端也只分别检查单个枚举，最终在供应商处理时才被拒绝。

## 当前规则

| 工作流 | 480p / 768p | 1080p / 2K |
| --- | --- | --- |
| 文生视频 | 21:9、16:9、4:3、1:1、3:4、9:16 | 16:9、9:16 |
| 参考视频 | adaptive 及以上六种固定比例 | 16:9、9:16 |
| 图生视频、Avatar | 保持已有源图流程，不发送 `aspect_ratio` | 保持已有源图流程，不添加未提供的输出比例参数 |

高分辨率限制依据用户提供的真实供应商校验错误；fal 页面列出的通用比例枚举不能代表每个分辨率均支持全部组合。此次未修改源图裁剪或推断图片尺寸。[fal API 参数](https://fal.ai/models/heygen/heygen-video/text-to-video/api)

## 修改

- `heygen-video-options.ts` 统一定义高分辨率组合规则和横竖屏回退。
- `videoModelRatios` 增加可选分辨率参数；HeyGen 的高分辨率文生/参考工作流只返回两个合法比例，其余模型保持原行为。
- 切换至高分辨率时，保留原有合法 16:9/9:16；3:4 调整为 9:16，方形和其他不兼容比例调整为 16:9。界面提供 16 种语言的说明。不会修改用户文本、参考素材、选择的时长或主动降分辨率。
- URL/草稿还原、模型切换和预设选择同样使用分辨率对应的比例；短暂不兼容状态禁止提交。
- 生成 API 在创建/扣款/付费提交前返回 `heygen_resolution_aspect_ratio`。旧客户端或直接 API 请求不能绕过组合校验。
- AI 润色 API 在请求 LLM 前验证同样的组合，避免为错误参数调用润色服务。

## 验证

- 模拟真实生成路由：1080p、2K 下的四种不支持比例和参考视频 adaptive 都在扣款前拒绝；两种合法比例可以按原参数提交。原有 480p/768p、图生视频、参考视频、Avatar 和计费回归保持通过。
- 手机/桌面浏览器回归：1:1→1080p 自动变为 16:9、3:4→2K 自动变为 9:16；低分辨率恢复更多选项；不兼容深链接修正；提示本地化，提示词保留。
- `npm run check` 含全部单测、模型/支付/安全回归和生产构建；浏览器接口全部模拟，没有付费生成或生产数据库修改。

验证记录：`outputs/video-dialogue/hd-check.log`。浏览器检查脚本：`scripts/verify-studio-loading-ui.mjs`。
