# Gemini Omni Flash 1.2

依据本次提供的两份 fal 文生视频、图生视频接口文档，将原 Omni 模型原位升级至 1.2；内部 provider `gemini-omni-flash-video` 不变，已有任务、历史计费和收藏入口继续可读。

- 文生视频：`google/gemini-omni-flash/v1.2/text-to-video`。
- 图生视频：`google/gemini-omni-flash/v1.2/image-to-video`。
- 分辨率：360p、720p、1080p、4K；默认 720p。
- 时长：3–15 秒；默认 8 秒。添加尾帧后，时长选项和服务端请求均限制为 3–10 秒。
- 比例：16:9、9:16；保留原有选择。
- 音频原生包含，不发送文档未提供的音频开关或 seed。请求记录中的音频状态保持开启。
- 首帧使用 `image_url`，可选尾帧使用 `end_image_url`；继续拒绝超过两张图片和图生视频缺少首帧的请求。

## 计价

按新文档的每秒价格计费，文生与图生相同，原生音频与输入图片不额外计费。保留项目现有换算：供应商美元成本 × 150；720p 及以上沿用 1.2 系数，360p 沿用基础系数 1；最后向上取整。

| 分辨率 | 供应商美元/秒 | 8 秒预估积分 |
| --- | ---: | ---: |
| 360p | 0.0273 | 33 |
| 720p | 0.0819 | 118 |
| 1080p | 0.1229 | 177 |
| 4K | 0.2457 | 354 |

共享规则同时用于前端预估、服务端规范化及提交。加入尾帧的请求先按 10 秒上限规范化，再计算扣分与保存任务设置，避免按照 15 秒收费却只生成 10 秒。fal 通用价格接口若缺少分辨率维度，不覆盖这里明确的四档报价。旧页面报价与新报价不同时返回 `video_price_changed`，不扣分或提交生成，待用户确认新价格后重试。

## 部署与验证

无需数据库迁移或新增依赖，沿用原部署命令。若线上配置了 `FAL_MODEL_VIDEO_GEMINI_OMNI` / `FAL_MODEL_VIDEO_GEMINI_OMNI_I2V`，应更新为上述 1.2 路径，或删除覆盖值；环境变量的显式覆盖仍然优先。

`npm run verify:video-keyframes` 包含新 Omni 回归：实际生成路由、四档分辨率、3/10/15 秒、图片顺序、尾帧上限、独立价格样本、旧报价拒绝以及保存的任务设置。`npm run verify:pricing` 校验现有积分策略，`node scripts/verify-video-keyframes-ui.mjs` 验证桌面/移动端选项与实际浏览器请求。所有生成、支付和数据库响应均模拟，不执行付费生成。
