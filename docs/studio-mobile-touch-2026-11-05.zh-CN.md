# Avatar 移动端滚动与工作区切换

本轮仅调整前端布局、导航与弹层交互，保留模型、生成 API、积分、登录和路由数据行为。

## 滚动修复

- 手机端取消工作台内层 `overflow-y: auto` 与 `overscroll-behavior: contain` 的组合，由页面承担纵向滚动。Avatar、音频以及视频编辑区不再吞掉滑动手势。
- 手机 Studio 的横向溢出使用 `clip`，避免主容器与全局 body 样式生成额外纵向滚动上下文，并使顶部栏能正常保持在视口内。公开页面不受该作用域影响。
- 顶部层级高于页面底部导航，菜单中的语言按钮不再被底部导航覆盖；生成按钮仍在正常文档流中。

## 切换入口

采用用户反馈后的最终设计：将切换入口融入当前工作区标题，例如“图像工作台 ⌄”，不增加单独的一排导航。点击后展开视频、图片、音频和数字人四个入口，显示当前选中项，继续使用已有的 Studio 客户端路由。

菜单支持 Escape、焦点限制、关闭后焦点返回、切换路由关闭、切换到桌面宽度关闭，以及与原手机主菜单互斥。标题菜单通过遮罩限制背景触摸，不改变 body 的 overflow，避免在页面底部打开时顶部栏跳动。桌面保留原有侧边栏和页面标题。

切换标题、工作区名称及辅助标签覆盖 16 种语言；深浅主题沿用现有 Tokens。

导航顺序统一为“首页 → 视频 → 图片 → 音频 → Avatar → 项目”，之后保留邀请／账单入口。桌面侧栏、手机主菜单、底部导航和标题菜单均从同一份列表取顺序，移除桌面独立排序，避免两端再次出现视频与 Avatar 位置不一致。

## 验证方式

专项脚本使用 Chrome 移动视口与可信触摸事件，实际派发 touchStart／touchMove／touchEnd 验证滑动，不用程序滚动代替触摸来证明可达性。覆盖四个可用 Avatar 模型及旧模型链接的现有回退、360／390／430px 和小高度窗口、工作区切换及历史导航、语言菜单滚动锁、RTL 与桌面兼容。

报告与截图：`outputs/studio-mobile-touch-20261105/`。账户与接口响应仅在测试浏览器内拦截，无实际生成、付款或数据库写入。

最终验证：生产构建、16 语言字典、Studio 输入／导航性能／账单检查通过。六组移动端触摸检查通过，四种可用 Avatar 模型与旧链接回退均到达文档底部，菜单键盘与主菜单互斥检查通过；既有提示、语言、余额与嵌套付款弹窗检查通过，客户端异常为 0。
