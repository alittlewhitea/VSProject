# H3 Max Turbo 每日免费生成

## 适用规则

- H3 Max Turbo，480p、5 秒，每个符合资格的账号每天一次生成机会。文生视频、图生视频和使用同模型的 Avatar 共享一次，不分工作台重复领取。
- 必须实际领取过 **100 积分注册奖励**，根据注册奖励流水判定。15 积分、历史 10 积分及同 IP 未获注册奖励的账号均不符合。
- 以实际注册奖励记录为准，不根据当前访问地区重新授予资格。切换地区不会把 10/15 积分账号变成符合资格的账号。
- 北京时间每天 00:00 重置，仅重置当天次数；IP/设备的归属不重置。
- 首次领取时绑定当前 IP、签名设备 ID，以及存在时的注册 IP 哈希。任何一个身份已经属于其他账号，均不能领取；同账号更换 IP/设备也不能在当天重复领取。
- 余额为零仍可使用免费机会。免费次数用完、不符合条件、其他分辨率或时长，按正常积分消费。
- 免费生成一经创建任务并进入提交阶段，即计为当天一次尝试，包括随后供应商报错或排队失败的情况。这样不会通过无限重试产生不受控的供应商费用。任务创建和额度记录任一步骤失败会整体回滚，不消耗机会。
- 低赠分国家的新注册奖励由 10 改为 **15 积分**。不回改历史流水，不自动补发旧账号的差额。

## 账务与并发

免费次数由服务端判定。请求只表达免费意图，不能自报国家、IP、设备哈希或注册奖励金额。

锁定积分账号后，依固定顺序锁定 IP/设备身份，再检查每日额度。零积分任务创建、身份归属及每日额度在同一 MySQL 事务内提交。任务唯一键和每日主键阻止并发重复领取。

免费任务保存 `estimated_credits=0`、`billing_source=daily_free`、`free_program=h3_turbo_480p_5s`。不会给账号充值 15 积分，也不会生成积分扣费或正数退款。后续任务状态同步继续使用已有流程。

如果用户看到免费，但提交时额度已被其他请求占用，返回 409，并提示重新确认费用，绝不自动切换为积分支付。免费存储不可用时返回错误或关闭免费展示，不绕过校验。正常积分任务继续可用。

## 数据库部署

先在网站数据库执行 [migration/add-h3-daily-free.sql](../migration/add-h3-daily-free.sql)，再部署代码。只新增两张表，不修改既有余额：

| 表名 | 用途 |
|---|---|
| `h3_daily_free_identities` | IP/设备哈希的首次领取账号归属，身份主键唯一 |
| `h3_daily_free_usage` | 北京日期 + 账号的每日记录，任务 ID 唯一 |

宝塔数据库管理工具中选中 DreamFace 对应数据库，执行 SQL 文件内容即可。该迁移已同步到全量建库脚本；现有站点只执行增量文件。不要清空身份表，否则会重新开放已绑定身份的免费资格。

不需要新的环境变量。设备签名沿用已有 `SIGNUP_IP_SECRET`、`AUTH_SESSION_SECRET` 或 `MYSQL_PASSWORD`，按此顺序取第一个存在值；密钥应保持稳定。生产部署依赖已有反向代理正确覆盖真实 IP；新注册赠分仍沿用已有国家头识别。缺失真实 IP 时关闭免费资格。

设备 ID 是浏览器中的一年期 HttpOnly 签名 Cookie `df_generation_device`，不是硬件指纹。多账号共享同一 Cookie 时会被识别；清空全部浏览器数据或更换浏览器可能改变设备 ID，因此仍同时检查 IP、注册 IP 和账号每日记录。不能保证识别同时更换网络和浏览器身份的人。

## 页面与验证

免费资格异步加载，不阻塞其他模型。符合条件的 5 秒/480p 设置显示“今日免费生成”和 0 积分，使用后恢复 15 积分。切换到 768p、1080p 或长视频使用各自正常价格。重新聚焦窗口、跨过每日重置时间或生成结束后刷新资格，避免沿用过期免费状态。

验证：`npm run verify:h3-daily-free`、`npm run check`。测试覆盖国家赠分、旧奖励资格、设备签名、共享 IP/设备、账号换身份、每日重置、并发、回滚、幂等、实际生成路由零扣费和明确的付费重试，不调用生产数据库或付费接口。
