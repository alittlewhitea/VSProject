# SEO / GEO 第二阶段

本轮以 2026-10-23 增长方案、后续功能落地页与当前产品配置为依据。完成可部署的第一批内容和度量工具；不把页面发布、抓取测试或搜索结果链接记为真实收录、排名或 AI 引用成绩。

## 搜索内容与产品事实

- 新增 `/avatar/ai-avatar-generator`：英语核心功能页，独立 title、description、canonical、FAQ 与面包屑；覆盖照片数字人、人物库、脚本、步骤、费用和限制，CTA 精确进入 Avatar 工作区。
- 新增 `/video/examples`：现有 H3 Turbo、Grok 和 FLUX 视频供应商演示，共六个文生/图生案例。展示原提示词、来源、模型、参数和按当前项目计价的积分估算，并允许打开相同设置。它们使用不同场景，不能据此宣称质量排名、我们实测的生成时长或历史实际费用。
- 文生视频与图生视频功能页加入同一组有来源的案例；其他语言已有内容保留，不生成没有审核的翻译页面或 hreflang。
- Omni 专题改为实际接入的 1.2 文生/图生能力及费用，移除上传视频编辑、对话式改片、语音克隆等未接入能力的承诺。缺少经过核验的 1.2 输出时，不将旧演示标为 1.2 新测试。
- 页脚、案例页与工具页互链；新页面加入 sitemap，并只更新确实修改过的页面日期。使用 WebPage、FAQPage、真实面包屑；没有编造评分、发布时间或 VideoObject 元数据。
- Gallery 从已发布记录服务端输出首屏条目和普通详情链接，保留客户端筛选及刷新。数据库不可用时不伪造可收录的案例详情。

## 入口归因与业务漏斗

入口为 `/admin/growth`，Admin 总览新增 Growth 按钮。接口仅允许原有管理员鉴权；公开页面只上传匿名观察事件，不公开用户或订单明细。

1. 根布局的 GrowthTracker 只识别白名单公开营销页，记录 `landing_view` 与进入 Studio 的 `landing_cta_clicked`。Studio、登录、账户和管理页不产生新落地页记录；常见机器人 UA 的落地页事件忽略。
2. 首次公开访问创建 30 天签名 HttpOnly / SameSite=Lax cookie，生产环境 Secure。只保存规范路径、来源分类、UTM 标签、外部域名、首次观察时间和不含凭证的浏览器归因 ID；不将登录 token、点击 ID 或来源 URL 查询串写入该 cookie。当前渠道区分自然搜索、AI 引荐、Google/Bing 等付费搜索、其他活动、外链与直接/未观察到来源。
3. 用户继续浏览、OAuth 回跳或支付返回，不覆盖既有首次触达。显式 Google 点击参数优先于自然搜索分类；ChatGPT 等 UTM 来源即使没有 referrer 也可识别为 AI 引荐。浏览器提供的来源是观察信号，签名不能证明访问者确实来自某次搜索或回答。
4. 只有服务端实际新建用户时，才把有效 cookie 关联到 `users.raw_user_meta_data.growthAttribution`，保留原有其他用户信息，且不覆盖已有归因。老用户登录不计为注册；缺少 cookie、换设备或写入失败时保持未知，不猜测历史来源。
5. 访客与工作区点击以第一触达浏览器 ID 去重。注册从用户事实表计算，激活须有 `transport=real`、`status=completed` 且有输出的任务；排队、失败、mock 或重复前端回调不增加激活用户。付费按至少一笔 completed 且金额大于零的积分订单去重为用户数，不把多次订单当成多位首购用户，也不把它当净收入。
6. 提供 7/28/90 天窗口：漏斗采用窗口内首次观察并注册的 cohort，再看同批用户当前真实生成和付费状态。窗口内注册但首次触达早于窗口的用户单独提示；缺失来源的新增用户单列 Unknown。激活率和付费率以同批注册用户作分母，不把不同观察窗口的访问与注册相除。

无需数据库迁移，复用现有 JSON 和事实表；沿用现有服务端签名密钥。归因和分析失败不会阻止登录。历史任务、订单、计费与 `login_success` 去重逻辑不重写，不修改 GTM 容器。

## 验证与后续观察

- `npm run verify:analytics` 新增 `verify-growth.mjs`，验证公开路径、来源分类、签名与篡改、首次来源保留、新用户关联、未知来源、真实任务/订单口径和管理员鉴权；用隔离数据验证页面原始 HTML 中的案例与 Gallery 详情链接。
- 浏览器验证桌面/移动端页面、案例 CTA 的工作流/模型/参考图、匿名访问与来源事件、管理页窗口切换、异常状态及手机布局；全部业务 API、GTM、数据库和生成响应隔离，不运行付费生成。
- 上线后以真实入口事件开始建立基线。GSC 的收录、搜索词、国家和设备报表以及 GA4 交付需在对应平台核验；本地成功不等于搜索平台已收录。
- `docs/geo-observation-template.csv` 是固定问题记录底稿。保持平台、地区、语言、搜索开关一致，每个问题独立观察三次，保存原始回答、是否有可点击的 dreamface.io 引用及引用页面。未实测字段为 NA，不以内部抓取或访问引荐冒充引用。
- 下一批原创对照实验应使用有权使用的同一素材、统一任务与参数，并保存失败和重试成本。当前没有新付费实验或代用户向外部平台发消息。
