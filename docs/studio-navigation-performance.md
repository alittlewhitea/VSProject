# 工作台切换性能排查

## 发现

工作台首页、图片、视频、音频和项目都是 `/studio` 的不同查询参数。`page.tsx` 是动态服务端入口，实际编辑器由同一个 `StudioContent` 客户端组件读取 `useSearchParams` 决定显示。

此前 PC 侧栏、手机底栏、手机菜单及首页入口使用默认 Next Link；模型与工作流按钮使用 router.replace。改变查询参数会走服务端导航，在网络响应和页面数据解析完成前保留旧界面。多个入口还存在不必要的路由预取。这能解释网络或服务器繁忙时“点击没反应”的等待来源。

工作台首页包含一个主预览和四个示例预览，原有可视区域策略会让同时可见的视频一起循环播放。在大屏上容易同时解码多路视频，在手机上增加 CPU/GPU、网络和电量负担。

## 修改

- `studio-link.tsx` 和 `lib/studio-navigation.ts`：仅拦截当前 `/studio` 内的同源普通点击，使用 Next 15 已支持的 native History 更新查询参数；useSearchParams、地址栏和前进后退继续同步，内部入口不做服务器预取。
- PC 侧栏、手机底栏/菜单、首页入口、项目卡片、页头使用同一个链接组件。模型、工作流、参考图片以及生成后的项目跳转使用同一个导航辅助函数。
- 保留 Ctrl/Cmd/Shift、鼠标中键、新标签、下载、跨站链接和账单/登录等真正页面跳转的原行为。
- 工作台首页预览加入独立播放组，最多一段可见视频播放；离屏、隐藏标签页或离开首页时暂停并清理。其他页面的预览行为不变。
- 不修改数据库、生成模型参数、计费、登录或 AI 增强调用逻辑。

## 验证

新增 `npm run verify:studio-performance` 并纳入 `npm run check`。执行真实导航组件与辅助函数，验证图片/视频/音频/项目/首页切换没有 fetch、push/replace/back/forward、滚动和特殊点击的语义，以及内部入口使用统一组件。执行真实视频组件的 Hook 生命周期，验证五个可见预览最多一个播放、离屏转交播放、隐藏标签页暂停和卸载清理。

改动前的生产构建，本机模拟 RSC 请求返回约 37 KB 页面数据，三条查询的本地 HTTP 往返约 10–95 ms。这个数值只表示本机服务器请求成本，不是实际手机或线上用户的点击延迟。修改后内部切换不再需要该 RSC 请求，但 Gallery、积分、任务等正常业务请求仍然保留。

当前没有连接的浏览器控制会话，因此未进行实际 PC/手机的点击计时、CPU 降速或网络限速测试，不能报告真实设备上的改善倍数。通过组件回归、类型检查、全项目检查和生产构建，并提供生产模式本地预览供实机查看。

改动不降低首屏约 434 KB 的 First Load JS；低带宽或低性能设备的初次 JS 下载和 hydration 仍可能需要时间。本次针对进入工作台后切换各创作模式的额外服务器等待与多视频同时播放。
